# FastapiAdmin 通用软件使用证明设计

## 1. 目标

为 FastapiAdmin 通用框架增加一套轻量、产品中性的软件使用证明能力：

- 租户管理员可在线预览并下载 PDF；
- 平台管理员可查询、预览和下载所有租户的软件使用证明；
- 证明包含固定唯一编号和二维码，可通过公开页面核验；
- 证明内容实时读取租户主数据、授权信息和系统配置；
- 不引入人工签发、续签、补发、换号、吊销或证明历史生命周期。

默认模板只是框架占位模板。基于 FastapiAdmin 开发的具体产品可替换模板及系统名称、版本配置，而不修改证明的数据和接口逻辑。

## 2. 核心原则

1. 一个租户对应一个固定证明身份。
2. 证明编号和公开 token 创建后不变。
3. 企业名称、统一社会信用代码、软件名称、软件版本、授权日期和租户状态均实时读取，不保存业务快照。
4. 当前请求 IP 不落库，仅在有权限用户的在线预览和 PDF 中实时显示。
5. 公开查验不显示 IP，也不暴露租户内部数据。
6. 无独立证明业务表；证明身份字段直接归属租户。

## 3. 数据设计

在 `platform_tenant` 增加：

- `usage_certificate_no`：固定、唯一、不可通过业务接口修改的证明编号；
- `usage_certificate_token`：固定、唯一、高熵的公开查验 token；
- `usage_certificate_created_at`：证明身份首次建立时间。

默认编号格式：

```text
FA-SW-{创建时租户编码}-{6 位随机码}
```

例如：

```text
FA-SW-ACME-A7K9Q2
```

租户编码以后即使被平台管理员修改，证明编号也不变化。数据库分别对证明编号和公开 token 设置唯一约束。

迁移时为所有现有租户一次性补齐三个字段。以后创建新租户时，在租户创建事务中同步生成；唯一值冲突时安全重试，确保租户创建与证明身份建立保持原子性和幂等性。

## 4. 实时数据来源

每次预览、下载或公开查验均读取当前数据：

- 企业名称：租户主数据；
- 统一社会信用代码：租户主数据；
- 软件名称：现有系统配置；
- 软件版本：现有系统配置；
- 授权起止日期：租户当前授权信息；
- 当前状态：租户状态和授权日期实时派生；
- 当前请求 IP：仅认证后的证明预览和 PDF 请求动态取得。

展示字段为空时统一显示 `-`。不新增证明专用配置页面，不展示签发主体。

## 5. 当前有效性

当前有效性不是持久化生命周期字段，而是读取时实时派生：

- 租户必须处于框架现有的正常可用状态；
- 当前时间不得早于已配置的开始时间；
- 当前时间不得晚于已配置的截止时间；
- 缺少某个日期边界时显示 `-`，该缺失边界本身不判无效；
- 禁用、过期或软删除租户判定为“当前无效”。

租户续期、状态变化或资料更新不生成新证明，也不改变证明编号和公开 token。

## 6. 页面与权限

### 6.1 租户管理员

在现有租户自助服务中增加“使用证明”入口：

- 刷新在线预览；
- 下载 PDF；
- 展示证明编号、企业资料、软件名称和版本、授权期限、当前状态、证明身份建立时间及当前请求 IP。

该入口仅租户管理员可见并可访问，使用独立权限码。普通租户用户既看不到入口，也不能直接调用接口。

### 6.2 平台管理员

增加软件使用证明查询页面：

- 按租户名称、租户编码、证明编号和当前状态筛选；
- 分页查询；
- 在线预览；
- 下载 PDF。

平台端仅提供只读操作，不提供编辑、签发、续签、补发、换号或吊销。

平台查询列表不显示 IP。平台管理员在有权限的证明预览或 PDF 中看到的是该次请求的当前 IP。

### 6.3 公开查验

二维码指向无需登录的 token 查验地址，例如：

```text
{站点公开地址}/#/certificate/verify/{token}
```

公开页面只展示：

- 证明编号；
- 企业名称；
- 统一社会信用代码；
- 软件名称和版本；
- 授权起止日期；
- 当前有效状态。

公开页面不显示 IP、联系方式、套餐价格、操作人或其他租户内部信息。

无效 token 统一返回“无法核验此证明”，不区分不存在、格式错误等内部原因。公开接口按高熵 token 精确查询并启用访问频率限制。

租户禁用、过期或软删除后，已有 token 仍可查询，但必须醒目标记“当前无效”。

## 7. 模板设计

默认模板采用已确认的 A 版“现代文档式”：

- A4 单页；
- 产品中性；
- 清晰、克制、打印友好；
- 软件名称和版本置于“企业软件使用证明”主标题上方；
- 主体信息采用清晰的字段布局；
- 二维码和公开查验说明位于页脚区域。

模板字段包括：

- 软件名称和版本；
- 企业软件使用证明主标题；
- 固定证明编号；
- 企业名称；
- 统一社会信用代码；
- 授权起止日期；
- 当前有效状态；
- 证明身份建立时间；
- 当前请求 IP；
- 公开查验二维码；
- “证明内容以系统当前租户及授权信息为准”的简短说明。

公开查验页使用相同的现代文档视觉语言，但只展示公开最小字段。

如果未配置可信的站点公开地址，认证后的预览和 PDF 仍可生成，但二维码区域显示“公开查验地址未配置”。系统不得根据请求 Host 猜测公开地址，也不得生成 localhost 二维码。

## 8. 预览与下载

### 8.1 HTML 在线预览

后端使用 Jinja2 和同一份证明模板实时生成 HTML。前端通过受控的 `iframe srcdoc` 展示，不把 HTML 作为下载文件提供。

### 8.2 PDF 下载

单份证明采用同步即时生成：

1. 用户点击下载；
2. 后端读取该时刻最新租户信息、系统配置和当前请求 IP；
3. 使用现有 WeasyPrint / `html_to_pdf()` 将同一 HTML 模板转换为 A4 PDF；
4. PDF 渲染调用放入线程池，避免阻塞 FastAPI 事件循环；
5. 接口直接返回 `application/pdf` 字节流和附件下载响应头。

不创建后台异步任务，不轮询任务状态，不保存 HTML、PDF、临时文件或 IP。建议文件名：

```text
企业软件使用证明-{企业名称}.pdf
```

只有未来新增批量生成或批量打包能力时，才另行设计后台异步任务。

## 9. 接口边界

接口分为三组：

1. 租户管理员：证明预览、PDF 下载；
2. 平台管理员：分页查询、证明预览、PDF 下载；
3. 公开访问：按 token 查询最小公开字段。

所有接口均为只读，不提供证明修改接口。具体路由沿用现有 `module_platform`、租户自助服务、平台权限和公开路由组织方式，并保持菜单、路由、后端权限和前端权限一致。

## 10. 错误处理与安全

- PDF 或二维码渲染失败时返回明确错误，不返回半成品文件；
- 当前 IP 不保存到数据库、日志扩展字段或证明身份记录；
- 公开 token 使用密码学安全随机值，不包含租户 ID、租户编码或可枚举序列；
- 公开接口只返回白名单字段并启用限流；
- 租户查询严格限制为当前租户，禁止跨租户读取；
- 普通租户用户无权访问预览和下载接口；
- 证明编号、token 和建立时间不可通过常规租户更新接口修改。

## 11. 验收标准

### 11.1 数据与迁移

- 所有现有租户迁移后具有唯一且固定的证明编号和公开 token；
- 新租户创建时自动生成证明身份；
- 重复初始化不会改变已有编号或 token；
- 租户编码修改后证明编号不变。

### 11.2 权限与隔离

- 租户管理员可以预览和下载；
- 普通租户用户被拒绝；
- 租户之间不能读取对方证明；
- 平台管理员可以分页查询、预览和下载；
- 菜单、前端入口、前端权限和后端权限一致。

### 11.3 实时数据

- 企业名称、统一社会信用代码、系统名称、版本和授权日期修改后，证明内容实时变化；
- 证明编号和公开 token 不变化；
- 不同请求 IP 在认证后的预览和 PDF 中正确变化且不落库；
- 平台列表和公开查验不显示 IP。

### 11.4 状态与公开查验

- 有效租户显示“当前有效”；
- 禁用、过期或软删除租户仍可查验并显示“当前无效”；
- 无效 token 只显示统一的无法核验信息；
- 公开接口不泄露白名单以外字段；
- 二维码打开对应公开查验页。

### 11.5 渲染与工程质量

- HTML 预览正确渲染产品中性 A4 模板；
- 下载结果是有效 PDF；
- 未配置公开站点地址时不生成错误二维码；
- 后端聚焦测试、租户隔离和权限测试通过；
- 前端权限测试、类型检查和生产构建通过；
- 新公开路由具有挂载测试，避免页面存在但接口未注册。

## 12. 明确不做

- 人工签发、续签、补发、换号或吊销；
- 证明历史版本或业务字段快照；
- 独立证明业务表；
- 单份证明后台异步生成；
- PDF、HTML 或 IP 持久化；
- 批量生成或批量打包；
- 证明专用系统名称、版本或签发主体配置页面；
- 公开展示联系方式、套餐、操作人或租户内部数据。
