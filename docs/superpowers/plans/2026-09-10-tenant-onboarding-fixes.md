# 租户开户与员工授权修复计划

**Goal:** 修复双实例浏览器实测的品牌配置403、部门树403、空角色缺少引导及站点0初值。

**Architecture:** 当前租户品牌接口只读、仅认证、从会话取租户并返回白名单；平台管理接口不放宽。用户页依照部门权限挂载树。角色保持产品自主授权，通过空状态入口闭合配置流程，中控只声明访问资格。单站点自动选择，多站点必须选择。

**Tech Stack:** FastAPI、Vue3、Vitest、pytest、Chrome/Playwright。

- [x] 品牌：新增 GET /platform/tenant/current/brand-config（AuthPermission()），复用 get_self_brand_config_items；config.store 改调无租户ID接口。测试普通会话白名单、缺失租户拒绝、管理接口不放宽及前端请求路径。
- [x] 部门：用户页仅 hasAuth('module_system:dept:query') 挂载部门面板；无权限不请求部门选项。只读浏览器验证无部门403，不能新增/编辑/删除。
- [x] 角色：用户编辑无可分配角色显示创建角色入口与步骤；无创建权限提示联系管理员。有角色时说明菜单和数据范围需要同时配置。中控状态显示访问资格含义、明确本地授权步骤，等待页与文档一致。不自动赋管理权限。
- [x] 站点：UI将0映射为未选择；合法单站点自动选中并请求对应套餐；多站点手选。验证新租户向导不显示0。
- [x] 定向测试、类型检查、差异检查；只重启预览后端。
- [x] 全新租户浏览器验收：开户、管理员登录、新员工授权、首次等待、创建角色、分配、员工查询、无报错；验证当前品牌不可越租户、管理接口拒绝及未授权写入拒绝。记录实际边界，不提交、不部署生产。
