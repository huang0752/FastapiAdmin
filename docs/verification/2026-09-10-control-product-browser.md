# 中控与产品授权浏览器验收

环境：本地 Control 3100 / API 8110，Product 3101 / API 8111，独立预览数据库；2026-09-10。
使用 Chrome 页面真实点击完成。验收账号 browseraudit0910（浏览器验收员工），产品自定义角色 browser_reader；测试数据保留供复查，不包含密码。

## 已验证

- 超管重新登录后应用中心展示全部应用、租户开通、开通进度与示例产品。
- 租户管理员从用户管理新增用户，选择示例产品并创建授权，弹窗显示已生效。
- 管理员从中控应用卡片单点登录产品，创建浏览器只读角色，打开权限树并保存用户查询权限。
- 产品用户管理给员工分配该角色，员工通过中控登录产品。
- 修复后员工系统管理仅有用户管理，查询按钮存在，新增按钮不存在。
- 中控撤权后员工在产品旧页面点击查询，返回登录页。
- 中控重新授权后，名单自动由同步中更新至已生效。

## 本轮修复

1. 权限树 ElTable 自带级联叠加业务级联：选择用户查询时会附带兄弟菜单查询权限。将表格 checkStrictly 设为 true，保留显式业务联动。组件回归复现修复前多选兄弟 ID，修复后及保存回填均仅保留目标、按钮与祖先；浏览器重新勾选保存并以员工身份验证。
2. 用户编辑表单显示不可修改的超管开关，角色选项包括不可直接分配的系统角色。隐藏编辑时超管开关、非超管新增时开关，过滤系统治理角色；角色出参补只读 is_system。浏览器确认开关消失及系统角色不再可选。
3. 授权名单提交后不追踪异步结果。仅有 pending/processing 时每 3 秒刷新；离开页面取消，完成后停止。浏览器确认重新授权自动变为已生效。

## 验证边界

本轮完成上述核心浏览器流程，不代表所有页面、所有数据范围组合或生产验收。开发热更新过程中曾出现 URL 已变化但旧页面暂留，刷新后恢复；该现象未纳入本轮修复完成的结论。现有历史角色可能保存过多余的查询菜单，本轮只重新配置验收角色，未批量改变既有角色权限。
