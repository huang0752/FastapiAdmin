# 新租户开户与员工授权浏览器实测

日期：2026-09-10。对象：`codex/unified-control-framework` 本地预览。

## 环境与方法

中控：http://127.0.0.1:3100/web/（API 8110）；产品：http://127.0.0.1:3101/web/（API 8111）。服务已在运行，本轮确认可访问后直接使用，没有重置数据库。两个实例分别使用预览数据库。

使用 Playwright 驱动本机 Chrome，通过实际登录、点击、表单提交完成操作；不是仅以接口测试代替浏览器。测试账号和租户保留，密码及浏览器认证状态仅存在本机私有预览目录，不进入本文或仓库。

测试租户 `browsertest0910x`，管理员 `browsertest0910x_admin`，员工 `browserstaff0910x`，产品本地角色 `auditreaderx`。

## 已走通

1. 中控平台管理员进入租户管理 → 新增，填写新企业，选择站点、基础版中控套餐、示例产品标准版，确认创建。
2. 创建成功并显示一次性管理员凭据；以新生成的管理员账号成功登录。
3. 新租户管理员用户列表只有本租户管理员。新增员工并勾选产品，授权状态自动变为“已生效”；列表变为本租户两名用户。
4. 新员工登录中控，未获得系统用户管理入口，应用中心只有已授权产品。
5. 点击产品卡片完成 SSO；员工首次进入产品等待授权页，没有自动取得管理员权限。
6. 新租户管理员通过同一路径 SSO 到产品，具备用户、角色管理能力，列表只显示该租户的管理员和员工。
7. 管理员创建自定义只读角色，在权限树仅勾选用户查询，分配给员工；员工状态变为已授权。
8. 角色默认“仅本人数据权限”时用户列表为空；将验收角色改为“全部数据权限”后，员工列表只显示本租户两名用户，未显示既有其他租户用户。员工没有新增按钮、编辑或删除操作。

## 发现的问题

### P1：登录时读取品牌配置使用了平台管理接口

中控与产品均捕获：`GET /api/v1/platform/tenant/5/config` 返回 HTTP 403 / code 10403“无权限操作”。正常租户账号登录时因此弹错。

代码对应：`config.store.ts` 登录后调用 `TenantAPI.getTenantConfig`；后端该路由要求租户查询权限，服务 `get_config_items` 还限制平台管理员。

建议提供认证后的当前租户品牌只读接口并只返回品牌白名单字段，不能通过向普通员工补授平台租户管理权限解决。

### P2：只授用户查询时仍请求部门树

员工已获用户查询权限，但进入用户管理仍请求 `GET /api/v1/system/dept/tree`，返回 HTTP 403 / code 10403 并弹错。用户列表本身能成功显示。

建议无部门读取权限时不加载部门树并隐藏相关筛选，或定义最小化、租户隔离的部门选项读取契约，不应被迫给只读员工授予完整部门管理权限。

### P2：开户后的本地角色配置缺少引导

中控显示“已生效”表示产品访问资格，不表示本地菜单已授权。新产品租户的用户编辑角色下拉框为空（系统 owner 角色不能直接分配）；必须先创建业务角色并配置菜单。手工流程已走通，但缺少默认业务角色模板及明确的后续引导。

### P3：站点初值显示为 0

租户创建向导的站点下拉框未选择时显示 `0`。手工选择“小柿 SaaS”后套餐正常加载，不阻断开户；应改为明确的未选择状态，或在仅一个合法站点时自动选择。

## 结论与边界

开户、管理员初始化、员工创建、跨实例 SSO、手工角色授权的主流程已走通，但存在上述实际 403 和初始化体验问题，不应评为完全通过。

本轮验证页面级数据隔离及按钮权限，未穷举直接 API 越权、并发、消息断线重试、全部套餐或生产环境。本轮未修改业务代码、未提交或部署，保留测试数据供后续修复回归。产品员工最终角色数据范围为全部数据权限，功能权限仅用户查询。


## 修复后复验（2026-09-10 18:17）

四项问题已处理：

- 新增认证只读 `GET /platform/tenant/current/brand-config`，只按会话租户返回品牌白名单，前端登录改用该接口。原平台租户管理与品牌编辑权限不变。
- 用户页无部门查询权限时不挂载部门树、不请求部门选项，消除只读用户无关403。
- 无可分配业务角色时显示步骤及“去创建角色并配置权限”入口；中控同步状态改为“访问资格已生效”，明确本地角色还需菜单和数据范围。等待授权页改成实际的编辑用户路径。没有自动授予业务或管理权限。
- 站点0映射为未选择；唯一合法站点自动选中并加载套餐，多站点仍需选择。
