# 产品内角色授权专项浏览器验收

日期：2026-09-10。中控3100、产品3101。使用Chrome真实点击，租户browserfix0910y、员工browserfixstaffy、本地角色fixreader。管理员和员工使用隔离浏览器上下文。

## 实测结果

- 员工持有产品本地只读角色时，用户查询可见、新增按钮不存在。
- 产品租户管理员通过用户编辑取消只读角色并保存。
- 原有员工会话立即请求用户列表，返回403/10403；页面点击查询也被拒绝。没有等待退出或令牌到期。
- 撤销角色后，员工重新从中控SSO进入产品，进入等待本地角色授权页。
- 管理员重新分配相同本地角色，员工重新登录产品可查询本租户用户，仍无新增按钮。
- 最终已恢复测试员工的只读角色。

## 新发现

撤销角色后，已经打开的旧页面没有自动更新菜单与分页总数：查询返回403、数据行清空，但菜单和“共2条”仍残留，并提示无权限操作。服务端授权撤销有效；前端需要在权限失效时刷新权限/菜单及页面状态，不能据此宣称整条撤权体验无问题。

本轮未修改业务代码。覆盖产品本地角色分配、撤销、旧会话拒绝、重新登录等待、恢复授权；未穷举角色禁用、多角色叠加、全部菜单或并发场景。凭据及截图保存在本机私有预览目录，不提交认证信息。


## 优化后复验

已修复旧页面残留：403触发一次最新权限检查，只有确认权限快照变化才清除列表缓存、标签和动态菜单；无菜单时转入待授权页。普通资源拒绝且权限未变化时保留当前页面，不重放失败操作。列表请求失败同步清零总数。

Chrome双上下文再次走通：已授权员工查询 → 管理员撤角色 → 旧会话查询403 → 旧页面自动离开并进入等待页（无旧菜单、数据或分页）→ 重新登录仍等待 → 管理员恢复角色 → 原等待页点重新检查 → 不重新登录即可恢复本租户查询，仍无新增权限。测试账号最终恢复只读角色。
